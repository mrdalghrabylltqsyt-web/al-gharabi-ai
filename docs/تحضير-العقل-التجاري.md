# تقرير تحضير «عقل المبيعات والنمو» — الغرابي AI

> **نوع الدفعة:** تحضير معماري فقط. لا تنفيذ للعقل التجاري الكامل.
> **التاريخ:** 2026-10-02 · **الإصدار:** 13.0.0 · **الفرع:** main
> **الهدف التجاري المركزي:** زيادة المبيعات الحقيقية الموثّقة لمعرض الغرابي — لا المشاهدات ولا المتابعين وحدهم.

## A. المعمارية الحالية (مصدر الحقيقة)

- **خادم Express مركزي واحد** (`server.ts`, ~1.9MB مُحزَّم): كل المسارات والحالة والمصادقة والتدفّقات.
- **محرّك الذكاء** (`engine/ai/*`): مزود Gemini واحد + حارس حصة مركزي (`firewall.ts`) + إعادة/مهلة/circuit breaker + بديل حتمي.
- **العقل المركزي متعدد المنصات** (`engine/brain/*`): إدراك، معرفة، ذاكرة، جمهور، سوق، أهداف، استراتيجية، تجارب، قرارات، تعلّم، دورات، dry-run، مسارات قراءة فقط.
- **سوشيال** (`engine/social/*`): سجل 10 منصات، موصلات حقيقية (Telegram/Facebook/Instagram/YouTube/TikTok)، تعليقات/ردود/نشر/مراقب 24/7، حارس سلامة محتوى، تقسيط حتمي.
- **الوكلاء** (`engine/agent/*`): منسّق + 19 أداة + صلاحيات 5 مستويات + مسارات.
- **التخزين** (`engine/storage/adapter.ts`): محوّل واحد — ملف محلي أو Postgres (`gharabi_state` key/value). لا migrations.
- **التعافي** (`engine/dr/*` + `tools/dr/*` + `dr-recovery-center/`): نسخ/استعادة/خزنة مفاتيح/PWA مستقل. **مكتمل — لا يُمسّ.**
- **الواجهة** (`src/*`): React RTL، ~37 مكوّناً، `AppContext` + `apiService`.

8. محرّك التنفيذ الكامل + ربط البيانات الحقيقية + مسارات + واجهة — **مؤجّل للدفعة التالية**.

## Q. نموذج مسار العميل المقترح

## S. حلقة التعلّم المقترحة

`OBSERVE → ANALYZE → HYPOTHESIZE → ACT → MEASURE → LEARN → UPDATE KNOWLEDGE → NEXT EXPERIMENT`
- تُبنى على `learningLoop` + `experimentEngine` + `memory/store` الموجودين.
- **لا «تعلّم» بلا آلية تحديث قابلة للقياس**: كل تعلّم = حدث بمصدر/عيّنة/`isFact`؛ أقوال AI تبقى فرضية.
- النتائج الحقيقية فقط (رد مُسلَّم/نشر متحقّق/بيع موثّق) تُغذّي التعلّم.

## U. المخاطر الأمنية

1. **تسريب بيانات عميل**: يجب ألا تُعاد أرقام/محتوى العملاء إلا للمصرّحين؛ لا تسجيل أسرار.
2. **تجاوز بوابات التنفيذ**: أي ربط مستقبلي يجب أن يمر بنفس `executeApprovedJob`/بوابات النشر.
3. **حقن عبر نص التعليق**: التصنيف حتمي لكن الرد يجب أن يبقى تحت حارس `contentSafety`.
4. **إساءة استخدام محرّك AI**: كل نداء يمر بجدار الحصة المركزي؛ لا مسار جانبي.

## V. مخاطر سلامة البيانات

1. **فقدان ثبات**: أي مفتاح جديد يجب أن يُسجَّل في طرفَي الحفظ (load/build) — درس موثّق متكرر.
2. **مزج أرقام مُختلقة**: يُمنع بأي ثمن — الطبقة الجديدة لا تُنتج رقماً بلا مصدر.
3. **انحراف عقد الأنواع**: `src/types` يجب أن يطابق استجابات الخادم (فحوص عقد قائمة).

## W. مخاطر الهجرة

1. **`workspace.products`** — إضافة حقول اختيارية فقط؛ لا تغيير شكل قائم، والقراءة متسامحة.
2. **الحملات** — إضافة حقول اختيارية؛ الحملات القديمة تُقرأ بلا كسر.
3. **لا schema migration**: الجدول key/value عام؛ مفاتيح جديدة تُضاف بأمان.

## X. ترتيب التنفيذ الموصى به للدفعة التالية

1. **ربط المخزن بالبيانات الحقيقية**: `buildCatalogFromWorkspace` + مسار owner لعرض/تحديث حالة الصدق + اعتماد المالك.
2. **ربط إشارات الطلب بالتفاعل الحقيقي** (`socialComments` + مراقب YouTube) في طبقة تجميع واحدة.
3. **مسار قراءة فقط** `GET /api/agent/brain/sales/state` (يعرض التقرير بلا تنفيذ).
4. **واجهة لوحة تجارية** (مخزن/طلب/فرص/مسار/ROI) تعرض بيانات الخادم فقط.
5. **حلقة تعلّم من نتائج حقيقية** (بيع موثّق → درس → ذاكرة).
6. **قنوات البيع الرقمي** (مبدأ platform-agnostic) بعد ثبات ما سبق.
